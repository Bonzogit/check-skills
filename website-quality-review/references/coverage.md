# 从策划预期得到本次检查范围

## 交接输入

读取当前版本的页面/模块蓝图、主要用户路径、视觉方向与参数、选中素材/组件、内容与后台映射，以及未决项。website-plan-design使用等价文档即可，不要求特定目录或某一模板。没有原方案时按用户需求和当前业务推导检查依据，标明推导来源；不要把验收者后来找到的参考倒写成原设计目标。

将关键预期列成“位置/路径 → 用户能观察到的结果 → 相关状态与设备 → 检查方式”。页面职责、主要行动、最关键图片/比较信息、核心反馈属于优先项；不必为每个像素增加记录。截图和操作日志按各自证明的结果引用，不能互相替代。

## 按任务选择

| 范围 | 最小覆盖依据 |
|---|---|
| 关键样板 | 主要任务走通、最难内容与素材状态、主方向保留、相关桌面/手机表达 |
| 完整交付 | 已交付页面职责与共用组件、主要跨页路径、声明的设备/语言/业务能力；页面内容不能被首页抽样替代 |
| 局部变更 | 修改组件及必要关联：改字体看真实内容与断点，改菜单看定位/返回/焦点，改询盘看上下文/保存/重试；不重跑无关邮件和部署 |
| 上线检查 | 当前公网版本、实际核心路径、部署记录与受影响数据保留；本地结果不当公网结果 |

设备覆盖按用户要求与影响确定。要求三端时包含电脑/平板/手机；手机Chromium/WebKit及窄屏、横向、触摸、焦点、减少动态按相关项执行。模拟环境标明模拟，不称实体Android/iPhone或微信实测。

## 未覆盖与复用

本次应查但没执行的项保留unverified及原因；不适用给产品或范围理由。通过的项不能把遗漏项“平均掉”。复用历史基线时保留其版本，说明适用范围；只有未受影响且仍有效的结论可沿用，不冒充本次新执行。

版本变化后复验受影响预期；工具失败或证据失效时保留未验证，不默默删除覆盖项。无需建立新工程才能制定覆盖：公开网页诊断也能以列表说明，只是本地记录检查器不负责验证远程证据。

机器记录采用1.1报告的coverage数组，每个本次预期对应一个检查ID；不同环境需要不同结果时拆开ID。填写当前具体期望，不把“检查通过”写成期望。检查器只验证你列出的覆盖关系，不会判断是否漏列整个页面或重要任务。
