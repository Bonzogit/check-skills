# 问题、优先级与复验

## 写成能执行的修复任务

每项包含：发生页面与位置、版本和环境、复现操作、原预期及依据、实际结果、访客影响、证据、根因归属、建议修改与复验条件。尚未确定根因就标记待定位，不先断言某个 CSS 或 API 已坏。

“手机不好看”不能交接；应指出哪个模块、在何种宽度、怎样溢出或遮挡、影响什么阅读或操作，以及完成修复后应呈现什么。审美问题也要描述可观察的关系，例如主次竞争、内容密度失衡、图片主体丢失，而非只报主观分数。

## 按实际影响排序

| 影响 | 处理依据 |
|---|---|
| 阻断交付 | 主要任务无法完成、数据丢失/错配、越权或关键业务承诺失真；先解决，不用视觉润色掩盖 |
| 主要缺陷 | 影响识别、阅读、判断或操作的明显问题，如关键内容缺失、主要按钮不可见、窄屏主要模块失效 |
| 一般缺陷 | 局部体验不一致或次要路径问题；结合发布范围处理 |
| 改进建议 | 当前任务仍完成且无明确违背要求；说明收益与代价，不冒充必修缺陷 |

不用缺陷总数判定质量。同一个根因造成多处问题可合并，但保留每个受影响位置；不可因严重问题只有一个就被许多轻微通过项稀释。

## 路由与复验

| 根因 | 返回环节 | 修复后核对 |
|---|---|---|
| 访客/任务假设、信息顺序、文案与行动逻辑 | 策划 | 原入口下的信息是否足以判断与行动，相关方案同步更新 |
| 真实资料缺失、图片错误、裁切计划不成立 | 素材准备；涉及构图时与设计协调 | 资产真实用途、授权状态、实际清晰度与各相关尺寸 |
| 布局、样式、焦点、菜单、动效与状态反馈 | 建站 | 原复现步骤、最终画面、受影响响应尺寸及返回/失败状态 |
| 内容模型、接口、翻译、询盘、交易与持久化 | 建站业务层 | 页面行为及实际保存/读取结果，不只看成功 toast |
| 构建、路由、版本、运行或部署 | 建站运行层 | 当前环境的真实版本与用户路径；不沿用本地结果冒充公网通过 |

状态依次记录 open → fixed-awaiting-recheck → verified；修了代码但尚未实际复验，不能直接 verified。采用既有报告格式时按其字段映射。延期或接受风险需记录理由，不能改成通过；超出授权或工具不可用时明确未验证。

复验保持原检查预期，等待可观察的完成状态。若需求确实改变，记录依据与新版预期；不能为了通过而删除失败断言、强制点击或掩盖加载问题。仅重测修改和必要关联，未受影响的旧结果保留版本与适用范围，不改写为本次新测。
