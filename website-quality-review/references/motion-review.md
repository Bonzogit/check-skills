# 动效和组件验收

读取实际选中的组件ID/版本、入口、依赖和行为预期。实验室索引、Hairline生成器或动画库的历史测试是选型信息，不是当前站通过证据。研究案例、可适配效果、独立组件与已验证组合分别识别；不能把演示后端与状态带入网站。

| 检查 | 实际动作与最终结果 |
|---|---|
| 起始/中途/结束 | 在当前真实浏览器观察对象、内容和命中区；终态可读、操作区稳定，没有依赖动画才出现的关键信息 |
| 滚动模式 | 依据方案区分一次播放、边界反复触发、进度可逆；检查正反向、停住、快速跨越、点击章节定位、末尾释放 |
| 中断/恢复 | 菜单/弹窗、切后台、离屏、返回页面、快速连续操作后状态可恢复，不留下遮罩、滚动锁或重复实例 |
| 手机/键盘 | 触摸不被指针交互抢走，页面原生竖向滚动可用；关键行为有点击/键盘入口，不只依赖hover |
| 减少动态/开关 | 系统偏好和站内开关按实际方案工作；静态或即时状态仍完整，不能把多阶段叠到同一行或隐藏内容 |
| 资源慢/失败 | 保留稳定占位和可用当前图；错误或GPU不可用时回退明确；恢复后行为可继续，不以空白当“正在播放” |
| 生命周期/性能 | 核对按需创建、暂停与销毁；对异常CPU/GPU/请求或布局跳动取实际证据，不能凭库大小猜卡顿，也不把低成本标签当本机性能实测 |

Hairline重点核对稳定命中、主题/强度实际支持、play与手动接管、暂停和减少动态；不拿抽象隐喻证明商品真实结构。表单/标签/菜单等组件还须接真实内容与回调：选择、跨页上下文、保存结果、失败恢复都要按当前版本确认。

结构检查、库已加载、DOM存在或截图采集成功不能证明播放正确。工具拿不到实时状态时明确缺口；不强制点击、不拉长等待掩盖状态错误。修复保留用户喜欢的表现，先处理命中区、滚动和生命周期，再判断是否需策划调整。
