# 网站成品验收

核对当前页面是否完成当前用户任务，输出可修复的问题与真实验证范围。读取项目版本、任务、设计依据、来源及建站已有检查；复用未受影响的有效证据。第一次固定基线；随后只检查变更及必要关联。完整新建覆盖整站必要路径，局部修补不重新研究整站。

## 执行

1. 确认网址/预览、项目版本、设备或视口、浏览器引擎、语言、动态偏好与复现步骤。服务重启后先确认版本与健康，再检查页面。代码与用户报告是线索，不可据模拟器正常否认真实设备问题。
2. 对照本次设计目标查看真实画面，检查产品识别、信息层级、图片裁切清晰度、标题换行、内容密度与下一步。参考与实现采用相同尺寸和相关状态；记录合理适配、明显偏差与未观察部分。截图比较能发现变化，不能自动判断好看。
3. 实际走受影响关键路径，检查进入、操作、结束、返回及失败恢复。用用户行为与最终状态断言；等待真实状态，避免强制点击或任意长等待掩盖问题。素材未加载完成的截图不能当最终画面。
4. 按 [检查选择](references/checks.md) 选择相应项。电脑、平板、手机和 RTL 在完整交付或用户要求时覆盖；局部改动只补相关尺寸。手机引擎按任务覆盖 Chromium/WebKit；视口、UA、触控模拟均不冒充实体手机或微信。
5. 记录问题严重度、复现条件、预期、实际、证据、负责人环节、修复状态和复验。产品定位/顺序问题返回策划；素材问题返回素材准备；布局、接口、业务与性能问题返回建站。一般缺陷可在授权范围修复，不能擅改设计方向或生产数据。

## 判定

每项状态只能是 pass / fail / unverified / not-applicable；不适用需理由，未执行需说明缺口。pass 必须对应当前项目版本、实际检查日期/方式/环境、用户可观察结果和有效证据。旧结果可作为历史或基线，不把它重标为当前已测。已查看的画面与已执行的操作分别报告。

业务开发测试由建站阶段负责，本 Skill 读取其结果并验证必要的页面行为、跨页面交接与遗留问题，不重复跑全部测试。后台编辑、翻译、询盘与邮件按当前任务选用：询盘入库、服务商接受、送达和实收分开；翻译任务 ready 与语言质量分开；构建、部署、公网可用分开。

沿用 [报告模板](assets/review-report.json) 写 `docs/review-report.json`，在既有交付报告简明解释结果，避免再造重复报告。`python scripts/review_check.py <project> --version <version>` 只检查记录结构与本地证据；`--require-pass` 要求声明的适用检查均通过且没有未解决问题。该工具不会浏览网页、读取图片含义、判断审美或认证网站质量。

## 停止与交付

优先修复阻断、数据错误、无法操作与明显视觉偏差；修改后定向复验。无新变更、失败或疑点就不重复扩大测试。存在 unverified 或未解决问题时逐项交付，不伪称全部完成；不要为保持记录全绿弱化验收预期。

本 Skill 不是独立评审者。相同执行者自检须如实说明；只有实际不同执行者进行了评审才可称独立评审。历史教训与证据边界见 [验收依据](references/evidence.md)。读取 Skill 不授权给客户发邮件、提交外部表单、重启生产服务、删数据或另建部署。
