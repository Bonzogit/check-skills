# 网站成品验收

判断当前网站能否清楚表达业务、帮助访客做决定并完成主要操作，输出可以直接修复的问题。产品展示、服务、内容、交易和工具网站按各自任务检查，不用同一张行业清单套所有网站。通用方法与具体网站的测试记录分开存放。

## 先明确验收对象

读取当前需求、页面方案、实现版本、需保留的设计与已有有效结果，确定网址/预览、范围、语言和设备。新建网站检查已交付页面与主要路径；局部修改只查受影响部分及必要关联。无法确认当前版本时先核实，不能拿旧站画面验收新版。

有策划方案就对照其模块目的、内容、视觉规格和操作预期；没有方案则从当前业务与用户需求建立最小检查依据，注明推导，不冒充原设计目标，也不要求先调用策划 Skill 重做全站。

按[策划交接与检查覆盖](references/coverage.md)将本次关键预期映射到页面、状态与环境，先明确应查什么再检查。完善本Skill时不启动网站项目；用户只要诊断时不自动修改或部署。局部任务不因完整检查表而扩大范围。

## 实际检查

1. **先看网站是否讲得清。** 陌生访客能否知道是什么、适合谁、差异是什么、如何继续；每页能否完成自身职责。核对事实、文案、比较维度、必要条件与行动目标。内容不足、顺序不合理与信息写死，不能被漂亮画面掩盖。
2. **查看当前真实画面。** 按[内容与视觉判断](references/quality.md)检查主次、密度、对齐、节奏、字体、标题换行、颜色、图片清晰度和裁切，以及不同页面的一致性。使用[参考对照](references/visual-comparison.md)区分合理适配、实际偏差与个人偏好，检查所选设计特征和媒体角色是否保留。图片未解码、淡入未结束或错误页截图不能当最终画面。
3. **走完主要用户路径。** 从实际入口进入，操作、确认结果，再返回或重试；检查产品/选项上下文、跨页交接和状态保存。表单验证到真实保存结果；交易验证到当前授权范围内的真实阶段，不能把跳转当成交。根据[检查选择](references/checks.md)覆盖相关失败、空态、加载、键盘、触摸与减少动态情况。
4. **按影响判断问题并分派。** 每项写明页面/位置、复现条件、预期、实际、影响、证据和建议修改，不只写“缺少高级感”。使用[问题与复验](references/remediation.md)区分定位/内容、素材、呈现、交互、业务和运行问题，优先解决阻断与影响主要判断的问题，不擅自换掉已确认设计。
5. **修复后只复验必要范围。** 以原用户行为和预期确认当前版本，核对关联状态是否受影响。没有新变化、失败或疑点就不继续扩大测试。记录真实工具与执行者，相同执行者自检不称独立评审。

涉及实验室、Hairline或其他动效时，读取[动效与组件行为](references/motion-review.md)，按当前选择的行为验收起止、反向、中断、恢复、销毁和减少动态，不以动画多或少判品质。保留用户确认的表现；先修交互与实现错误，不能为了让检查通过直接删效果。

## 结论与交接

对外先说明“当前可交付范围、主要问题、未验证项”，不要把检查数量或分数当成质量。逐项使用 pass / fail / unverified / not-applicable；不适用需理由，通过需对应当前版本、环境、实际结果和证据。检查器不能决定页面是否好看、内容是否可信或操作是否真正完成。

默认在当前网站已有报告中记录，避免重复造文档；需要机器检查记录时用[报告模板](assets/review-report.json)及 `python scripts/review_check.py <工程目录> --version <网站版本>`。新版1.1报告保留本次coverage预期，缺项不能靠只列通过项掩盖；1.0旧记录仍可检查，需报告其覆盖范围未知。字段与边界见[记录协议](references/report-contract.md)。`--require-pass` 仅约束已记录覆盖和问题状态，不代表整站认证。没有源码目录或本地证据时仍可验收公开页面，如实给报告，不为运行记录检查器新建网站。

内容和顺序问题交回策划；素材缺口交回素材准备；布局、交互、接口、数据和性能问题交回建站。业务开发测试由建站负责，本 Skill 复用有效结果并检查必要的用户可见链路。询盘保存、邮件供应商接受、送达/实收分别报告；翻译生成与语义质量分别判断；构建、部署与公网可用分别判断。

原数据、账号、附件、域名与部署目标继续保留。只读检查不需要发布网站；外部提交、测试邮件、生产变更按已有授权执行。证据边界与常见故障见[验收依据](references/evidence.md)。

本包核心方法与检查器自带，可将整个website-quality-review目录迁到其他电脑；Python仅用于记录检查，浏览器、实体设备、业务服务与原项目证据另行准备。外部辅助工具及与策划资料包的配合见[工具与迁移](references/tools-portability.md)，不依赖旧电脑路径或强制安装另一套Skill。
